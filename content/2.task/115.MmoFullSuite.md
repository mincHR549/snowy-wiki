# 纯 MMO 系插件完整方案

本方案与 [eco 生态替代 MMOCore 方案](/task/mmotoeco) 是并列的两个技术路线，供对比取舍。与 eco 方案不同，本方案**不引入任何 eco 系插件**，职业、技能、装备、专精、怪物全部使用 Indyuce / Ka0rX 团队维护的 MMO 系插件（MMOCore、MMOItems、MMOInventory、MMOProfiles 等），配合 MythicMobs 构成完整闭环。优势是官方 Typewriter Extension 覆盖面更广、插件间原生联动最完整；代价是版本追更相对 eco 系保守，且核心插件多为付费资源。

---

## [方案总览](#方案总览)

MMO 系插件全部构建在同一个底层库 **MythicLib（原 MMOLib）** 之上，插件之间共享属性、元素、技能语法，因此不需要像 eco 方案那样为职业层单独引入 Fabled 做桥接——MMOCore 本身就自带职业与主动技能释放系统。

---

## [插件清单](#插件清单)

### [1. 底层依赖（必装）](#_1-底层依赖必装)

## 核心库

**MythicLib**（原 MMOLib）

Indyuce 维护的核心依赖库，是 MMOItems、MMOCore、MMOInventory、MMOProfiles 的硬依赖。把四个插件共用的 RPG 机制（属性、元素、格挡/招架/闪避、技能语法、暴击特效）合并到一个库中，保证插件间原生兼容，同时每个 MMO 插件依然可以单独运行，不强制互相依赖。

**PlaceholderAPI**

暴露 MMOCore 等级/职业、MMOItems 属性等数值为占位符，供 Typewriter 剧情条件判断使用，用法与 eco 方案一致。

### [2. 职业与主动技能层](#_2-职业与主动技能层)

## 职业 / 技能释放 / 天赋树

**MMOCore**

Indyuce 维护，MMO 系的职业核心插件，自带完整的：

- 职业系统（class）与转职
- 主动技能释放（冷却、蓝耗、粒子特效，语法与 MythicMobs 技能高度相似）
- 天赋树 / 技能树（skill tree）
- 副职业（profession，如挖矿、伐木、钓鱼、附魔）
- 经验、属性成长、跑速/生命值随等级变化
- 传送点（waypoint）系统

与 eco 方案最大的差异在这里：**eco 生态没有把"职业+主动放技能"整合到一个插件里**，需要 EcoJobs（打工经济向）+ Fabled（主动技能释放）两个插件拼起来；而 MMOCore 一个插件就原生覆盖了这两层职责。

MMOCore 依赖 MythicLib 才能运行，建议搭配 MMOItems、MMOProfiles 使用以获得最佳联动效果，但三者均可独立运行，不强制捆绑安装。

### [3. 存档与多角色层（可选）](#_3-存档与多角色层可选)

## 多角色 / 跨服存档

**MMOProfiles**

允许玩家在同一账号下拥有多个角色存档（类似传统 MMORPG 的多角色栏位），并支持基于代理（Velocity/BungeeCord）的跨服存档同步。不装此插件时 MMOCore/MMOItems 均可正常运行，纯粹是锦上添花的模块。

### [4. 装备与背包属性层（必装）](#_4-装备与背包属性层必装)

## 自定义装备 / 属性物品栏

**MMOItems**

MMO 系装备体系的核心，提供：

- 自定义武器/工具/装备/消耗品，附带独立的属性面板（攻击力、暴击率、元素抗性等，均由 MythicLib 统一结算）
- 装备升级、宝石镶嵌、合成站
- 与 MMOCore 职业/等级挂钩的装备使用限制

**MMOInventory**（可选）

提供自定义装备栏位（如戒指、护符、腰带等额外槽位），扩展玩家能够穿戴的属性物品数量，属性同样通过 MythicLib 统一结算并叠加进战斗计算。

这一层无需二选一——本方案默认全程使用 MMOItems，无需像 eco 方案那样在 EcoItems 和 MMOItems 之间做取舍。

### [5. Boss / 怪物技能层](#_5-boss-怪物技能层)

## NPC 与 Boss 演出

**MythicMobs**

给自定义怪物/Boss 挂技能，技能语法与 MMOCore 的职业技能语法同源（均基于 MythicLib 的技能系统），学习成本低、迁移成本也低。与 Typewriter 有官方 Extension（MythicMob NPC），支持相机聚焦、动画、任务目标绑定。

**MythicCrucible**（可选）

MythicMobs 的自定义物品扩展，如果不想用 MMOItems 做特殊 Boss 掉落物，可以用它补充；但由于本方案已全程使用 MMOItems，通常无需额外引入。

### [6. 社交层](#_6-社交层)

| 插件 | 功能 |
| --- | --- |
| **Guilds** / FactionsBridge / KingdomsX / UltimateClans | 公会系统 |
| **PartyAndFriends** / Parties / OBTeam / DungeonParties | 队伍系统 |
| **DungeonsXL** / mcMMO | 地下城 / 副本模块（MMOCore 官方推荐搭配） |

社交层插件与 eco 方案完全共用，不受职业/技能体系选型影响。

## [完整安装顺序](#完整安装顺序)

1. `MythicLib`（核心库，必须最先安装）
2. `PlaceholderAPI`
3. `MMOCore`（职业、主动技能、天赋树、副业）
4. `MMOItems`（装备与属性物品）
5. `MMOProfiles`（可选，多角色/跨服存档）
6. `MMOInventory`（可选，额外装备栏位）
7. `MythicMobs`（+ 可选 `MythicCrucible`）
8. `Guilds`、`PartyAndFriends`（社交层）
9. `Typewriter` 及其对应 Extension（MMOItems Integration、MythicMob NPC）

---

## [与 Typewriter 的联动现状](#与-typewriter-的联动现状)

与 eco 方案相比，本方案在 Typewriter 联动上有明显优势：

- **MMOItems**、**MythicMobs** 均有官方 Extension，物品消耗/合成/宝石镶嵌事件、NPC/Boss 演出可以直接在 Typewriter 中触发，与 eco 方案一致
- **MMOCore** 目前同样未查到官方 Typewriter Extension，职业等级/技能数值的联动仍需通过 PlaceholderAPI 做单向条件判断，双向联动（剧情自动升级职业、剧情触发技能释放）需要自行监听 MMOCore 的 `PlayerLevelUpEvent` / `PlayerClassChangeEvent` 等事件后调用 Typewriter 的 `/typewriter trigger` 接口——这一点与 eco 方案中 Fabled 的桥接需求基本相同，**并没有因为选择纯 MMO 系而消失**。

也就是说，MMO 系相对 eco 系的核心优势不在"是否需要写桥接插件"，而在于**插件数量更少、语法体系更统一**（技能语法在 MMOCore/MMOItems/MythicMobs 之间共享，学习和维护成本更低）。

## [取舍总结](#取舍总结)

| 维度 | 纯 MMO 系 | eco 生态 + Fabled |
| --- | --- | --- |
| 完成度 | 高，职业+技能+装备原生一体 | 高，各模块开箱即用但分散在多个插件 |
| 插件数量 | 少（MythicLib + MMOCore + MMOItems 即可覆盖大部分需求） | 多（eco 核心库 + Fabled + Codex + EcoJobs + EcoItems 等） |
| 技能语法统一度 | 高，MMOCore/MMOItems/MythicMobs 语法同源 | 较低，Fabled 与 MythicMobs 技能语法体系不同 |
| 版本追更 | 保守，跟随官方稳定版本节奏 | 积极，官方支持 1.21.8+ |
| Typewriter 联动 | MMOItems/MythicMobs 有官方 Extension，MMOCore 层仍需自建桥接 | MMOItems/MythicMobs 有官方 Extension，职业/技能层仍需自建桥接 |
| 获取成本 | MMOCore、MMOItems 等为付费资源 | eco 系插件多为免费/开源 |
| 维护成本 | 插件少、语法统一，长期维护更省心 | 插件多、配置分散，需要跨插件对齐数值 |

## [与 eco 方案的关键区别一览](#与-eco-方案的关键区别一览)

| 功能层 | 纯 MMO 系 | eco 方案 |
| --- | --- | --- |
| 核心库 | MythicLib | eco |
| 职业 + 主动技能 | MMOCore（一体） | Fabled + Codex（职业与技能释放） |
| 副业/打工型专精 | MMOCore 自带 profession 模块 | EcoJobs（独立插件） |
| 装备属性 | MMOItems（+ 可选 MMOInventory） | EcoItems + EcoEnchants + EcoArmor，或保留 MMOItems |
| 多角色存档 | MMOProfiles（可选） | 无对应模块 |
| 怪物/Boss | MythicMobs（相同） | MythicMobs（相同） |
